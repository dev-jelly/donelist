<info added on 2025-11-13T13:46:56.363Z>
실제 워크로드 분석기 구현 완료. internal/performance/workload_analyzer.go에서 pg_stat_statements 기반 쿼리 패턴 분석, 미사용 인덱스 탐지(50회 스캔 미만), 높은 sequential scan이 발생하는 테이블 식별, 우선순위 기반 인덱스 후보 생성 및 CREATE SQL 문 자동 생성 기능 구현.

Checkins 테이블용 복합 인덱스 (user+time, category+time), FTS, 편집된 체크인용 부분 인덱스와 Analytics events용 user+type+time 복합 인덱스 및 대용량 테이블 파티셔닝 권장사항, Search history용 user+time 인덱스, Sync queue용 user+status+time 부분 인덱스 등 핵심 테이블별 스마트 인덱스 후보 생성.

CLI 도구 cmd/workload-analyzer/main.go로 analyze(전체 워크로드 분석), unused-indexes(미사용 인덱스 목록), missing-indexes(높은 seq scan 테이블), index-candidates(우선순위 인덱스 권장) 명령어 제공.

4단계 우선순위 프레임워크: Critical(사용자 타임라인, FTS, 동기화 큐-즉시 구현), High(카테고리 필터링, 분석-1주 내), Medium(검색 기록-향후 검토), Low(프리미엄 기능-선택사항). 

docs/WORKLOAD_ANALYSIS_GUIDE.md에 워크로드 분석 실행 방법, 우선순위별 인덱스 권장사항, 쿼리 패턴 분석, before/after 벤치마크 포함 인덱스 테스팅 방법론, 모니터링 모범 사례, CI/CD 통합 예제, 일반적인 인덱스 문제 해결 방법 문서화.

테스팅 접근법: 7일 기준선 수집 후 워크로드 분석기 실행, 각 인덱스 영향도를 EXPLAIN ANALYZE로 테스트, 실행 시간 전후 측정, 중요 쿼리에 대해 95% 이상 개선도 검증, pg_stat_user_indexes로 인덱스 사용량 모니터링 계획 수립.
