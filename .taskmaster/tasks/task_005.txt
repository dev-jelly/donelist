## 1. 시간 블록화 엔진 구현 (15/30/45/120분 지원) [done]
### Dependencies: None
### Description: 요청된 단위로 하루를 연속 블록으로 분할하고 체크인들을 블록에 매핑하는 코어 로직을 구현합니다.
### Details:
요청 파라미터 block=15|30|45|120을 수용하고 대상 날짜의 시작/끝 경계를 기준으로 블록 리스트를 생성합니다. 각 체크인을 소속 블록에 매핑하고 겹침 시 우선순위/합산 규칙을 정의합니다. 후속 단계의 빈 구간 채움·타임존 변환을 고려한 확장 가능한 인터페이스를 설계합니다.
<info added on 2025-11-12T16:55:50.686Z>
전체 시간 블록화 엔진 구현이 완료되었습니다. `timeline/service.go`에서 TimeBlock, CheckinWithMeta, Gap, DailySummary, CategoryLegend 모델을 정의하고, generateTimeBlocks, detectGaps, calculateDailySummary, buildCategoryLegend, enrichCheckinsWithCategories 헬퍼 메소드를 구현했습니다. `timeline_handler.go`에 GetDailyEnhanced API 엔드포인트(/api/v1/timeline/daily/enhanced)를 추가하여 블록 단위(15/30/45/120분), 타임존, 네비게이션 지원을 제공합니다. 라우팅도 `routes.go`에 등록되었습니다.
</info added on 2025-11-12T16:55:50.686Z>

## 2. 빈 구간 채움 로직 및 표시 상태 구현 [done]
### Dependencies: 5.1
### Description: 체크인이 없는 시간대를 자동으로 채워 사용자에게 연속 타임라인을 제공합니다.
### Details:
블록화 결과를 순회하여 비어있는 블록에 type='empty' 플래그와 duration, display_hint를 부여합니다. 연속 empty 블록을 옵션에 따라 압축/비압축 처리하고, 프런트가 시각적으로 구분할 수 있도록 reason 필드를 포함합니다.
<info added on 2025-11-12T16:57:25.091Z>
프로젝트 구조를 먼저 분석해보겠습니다.타임라인 관련 코드를 살펴보겠습니다.`detectGaps` 메서드의 구현을 찾았습니다. 이 메서드는 timeline/service.go:436에서 구현되어 있으며, 체크인들을 시간순으로 정렬한 후 연속된 체크인들 사이의 간격을 계산하고, 1분 이상의 간격이 있을 때 Gap을 식별하는 로직입니다.

구체적인 구현 사항은 다음과 같습니다:
- 체크인이 2개 미만이면 빈 갭 배열 반환
- 체크인들을 시간 순으로 정렬
- 각 체크인의 종료 시간을 계산 (시작 시간 + 지속 시간)
- 다음 체크인의 시작 시간과 현재 체크인의 종료 시간 비교
- 1분 이상의 간격이 있을 때 Gap 구조체 생성

detectGaps 메서드가 timeline/service.go:436-474에서 구현 완료됨. 체크인을 시간 순 정렬 후, 각 체크인의 종료 시간(시작시간 + 지속시간)을 계산하여 다음 체크인과의 1분 이상 간격을 Gap으로 식별함.
</info added on 2025-11-12T16:57:25.091Z>

## 3. 카테고리 색상 메타데이터 합성 및 범례 제공 [done]
### Dependencies: 5.1
### Description: 응답에 카테고리별 색상 정보를 포함해 클라이언트의 색상 코딩을 지원합니다.
### Details:
카테고리 테이블/설정에서 color_code를 읽어 사용된 카테고리 목록으로 범례(meta.legend) 배열을 구성합니다. 기본/미지정 카테고리는 fallback 색상을 적용하고, 색상 대비(AA) 확인용 text_color 필드를 계산합니다.

## 4. 시간대 변환 및 DST 안전 경계 계산 [done]
### Dependencies: 5.1
### Description: 요청한 타임존 기준으로 하루의 로컬 경계를 계산하고 UTC 저장값을 정확히 변환합니다.
### Details:
쿼리 파라미터 tz=IANA 식별자(예: Asia/Seoul, America/Los_Angeles)를 수용합니다. 로컬 자정 기준 day_start/day_end를 구한 뒤 DB 질의를 위해 UTC 범위로 변환합니다. 서머타임 전환의 반복/결손 시간도 안전하게 처리합니다.
